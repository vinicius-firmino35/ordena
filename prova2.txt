 RESUMO TEÓRICO DOS ALGORITMOS DE ORDENAÇÃO

###  Insertion Sort
- Insere elementos em uma lista ordenada, um por um.
- Melhor caso: O(n) (lista já ordenada).
- Pior caso: O(n²) (lista invertida).
- Estável e in-place.

###  Selection Sort
- Encontra o menor elemento e o coloca na posição correta.
- Complexidade: O(n²) sempre.
- Não é estável, mas é in-place.

###  Merge Sort
- Divide e conquista, separa a lista e depois mescla ordenadamente.
- Complexidade: O(n log n) sempre.
- Estável, mas usa memória extra (não in-place).

###  Quick Sort
- Escolhe um pivô, separa menores e maiores e ordena recursivamente.
- Melhor caso: O(n log n), Pior caso: O(n²) (se pivô for mal escolhido).
- Não é estável, mas é in-place.

###  Counting Sort
- Conta quantas vezes cada número aparece e monta a lista ordenada.
- Complexidade: O(n + k), onde k é o maior número.
- Estável, mas requer memória extra.

###  Radix Sort
- Ordena números por dígitos, do menos significativo ao mais significativo.
- Complexidade: O(d(n + k)), onde d é o número de dígitos.
- Estável, mas usa memória extra.

------------------------------------------------

 QUANDO USAR OU EVITAR CADA ALGORITMO

  Insertion Sort
Ok/ Para listas pequenas e quase ordenadas.
Nao/ Para listas grandes (\(O(n²)\)).

  Selection Sort

  Merge Sort

Nao/ Quando há pouca memória disponível.

  Quick Sort

 Radix Sort

 PERGUNTAS TEÓRICAS SOBRE ORDENAÇÃO

1 Qual a diferença entre ordenação por comparação e distribuição?
- Comparação: Usa comparações entre elementos (Ex: Quick Sort, Merge Sort).
- Distribuição: Usa características dos elementos (Ex: Counting Sort, Radix Sort).

2 O que é estabilidade? Quais algoritmos são estáveis?
- Mantém a ordem relativa dos iguais.
- Estáveis: Insertion, Merge, Counting, Radix.
- Não estáveis: Selection, Quick.

3 Quando Quick Sort tem pior desempenho que Merge Sort?
- Quando o pivô é mal escolhido, gerando \(O(n²)\).

4 Por que Counting Sort não serve para floats ou strings variáveis?
- Porque usa valores como índices em um array auxiliar.

5 Radix Sort é sempre melhor que os algoritmos de comparação?
- Não. Depende do número de dígitos \(d\), pois pode ser ineficiente se \(d\) for grande.

6 Qual algoritmo usar para ordenar milhões de registros em um banco de dados?
- Merge Sort (se precisar de estabilidade) ou Quick Sort (se estabilidade não for necessária).

7 O que é um algoritmo in-place? Quais são in-place?
- Ordena sem usar muita memória extra.
- In-place: Insertion, Selection, Quick.
- Não in-place: Merge, Counting, Radix.

8 Como Insertion Sort e Selection Sort lidam com listas parcialmente ordenadas?
- Insertion Sort: O(n) no melhor caso, ideal para listas quase ordenadas.
- Selection Sort: Sempre O(n²), independentemente da entrada.

9 Qual algoritmo usar para sistemas embarcados com pouca memória?
- Quick Sort ou Insertion Sort.

10 O que acontece se o pivô do Quick Sort for sempre o menor elemento?
- O Quick Sort cai no pior caso \(O(n²)\), criando partições desbalanceadas.
